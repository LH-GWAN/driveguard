# DriveGuard

차가 멈춘 뒤 운전자에게 응답을 확인하고, 답이 없으면 보호자와 구조자를 연결하도록 설계한 Pleos Connect 앱입니다.

현대자동차그룹 차량용 앱 개발 공모전 출품용 프로토타입입니다. **가상 데이터로 Pleos Connect 에뮬레이터에서만 확인했고 실차에서는 시험하지 않았습니다.** 구조를 보장하지 않고, 진단이나 예측을 하지 않으며, 119를 대신하지 않습니다.

## APK 위치

`apk/DriveGuard_release.apk` (release 빌드)

## 테스트 환경

- Pleos Connect Emulator v2.1.0 (API 34, arm64), Cold boot
- macOS, Apple Silicon. 다른 환경은 시험하지 않았습니다.
- Node.js 22 이상 (보호자 가상 서버). 외부 패키지는 쓰지 않습니다.
- JDK 17, Gradle 8.9 (빌드할 때)

## 실행 방법

1. Pleos Connect Emulator를 Cold boot로 켭니다. [공식 절차](https://document.pleos.ai/docs/connect/guide/getting-started/application-development/setup-connect-sdk-emulator)
2. 보호자 가상 서버를 켭니다. 실제 문자나 알림을 보내지 않습니다.
   ```bash
   cd guardian-mock && npm start
   ```
   브라우저에서 `http://127.0.0.1:8787/`을 열면 보호자 화면(가상)이 보입니다.
3. 저장소 최상위 폴더에서 APK를 설치하고 실행합니다. 이 AVD의 현재 사용자는 10입니다.
   ```bash
   adb install --user 10 "apk/DriveGuard_release.apk"
   ```
   ```bash
   adb shell am start --user 10 -n kr.driveguard/.ui.MainActivity
   ```
4. 동의 세 가지를 확인하고 권한을 허용합니다. 사전 입력에서 "견본 채우기"를 누르고, 기다릴 시간을 정한 뒤 저장합니다. "맞습니다"를 누르면 멈춤 후 응답 확인이 켜집니다.

## 필요한 설정

- 차량 값은 Virtual Console로 바꿉니다. `adb forward tcp:8088 tcp:8088` 뒤 브라우저에서 `http://127.0.0.1:8088/`을 엽니다. 터미널에서는 `scripts/vc.sh`를 쓸 수 있습니다. 콘솔은 브라우저 세션 신호가 있을 때만 활성화되므로 터미널만 쓸 때는 `scripts/vc.sh session`을 켜 둡니다.
- 위치는 `adb emu geo fix <경도> <위도>`로 정합니다.
- 소스에서 빌드: `./gradlew :app:assembleDebug`. release 서명은 저장소 밖의 키와 `keystore.properties`가 필요합니다.
- 테스트: `./gradlew :app:testDebugUnitTest`, `cd guardian-mock && npm test`
- 음성 입력 시험: debug 빌드만 합성 음성 파일을 넣을 수 있습니다. `adb shell am broadcast --user 10 -a kr.driveguard.debug.SAY -p kr.driveguard --es file help.pcm` (`help`, `ok`, `end`). release APK에는 이 훅이 없습니다.

시연 절차는 [docs/시연시나리오.md](docs/시연시나리오.md), 확인 결과는 [docs/검증결과.md](docs/검증결과.md), 보안 점검은 [docs/보안체크.md](docs/보안체크.md)에 있습니다.

## 동작

앱은 차량 상태를 해석하지 않습니다. 멈춰 있고 조작 변화가 없으면 묻고, 답이 없으면 정해 둔 연락과 차량 동작을 합니다.

| 단계 | 조건 | 앱이 하는 일 |
|---|---|---|
| 도움 요청 | 화면 "도움 요청" 버튼(기어 P에서만 보임). 주행 중 음성 호출 방법은 미정(시연은 debug 빌드의 합성 음성 주입). "도와줘", "가슴이 아파" 같은 말은 증상을 해석하지 않고 모두 같게 처리 | 안전한 곳에 세우라는 음성, 가까운 쉼터를 내비에 설정, 취소가 없으면 보호자에게 위치 전송 |
| 응답 확인 | 속도 0, 기어가 P가 아님, 정해 둔 시간 동안 조작 변화 없음 | "괜찮으세요?"를 두 번 묻기 |
| 응답 없음 | 두 번 모두 답이 없음 | 보호자에게 119 신고 판단 요청(위치, 지도 링크, 정차 시각, 마지막 응답 시각), 운전석 창문을 조금 열기, 동승자에게 음성 안내. 앱은 119에 직접 연결하지 않음 |
| 기어 P 이후 | 응답 없음을 거친 뒤 속도 0, 기어 P | 고지와 취소 시간 뒤 문 잠금 해제, 실내등, 미등, 글러브박스(응급약이 있을 때), 앱을 여는 방법 안내 |
| 구조 화면 | 이 단계에서만 (차가 3초 이상 움직이면 가림) | 입력해 둔 병력, 복용약, 응급약 위치, 보호자, 마지막 응답 시각, 정차 시각 표시 |
| 종료 | 차 안의 화면 또는 음성 "종료" (아래 취소 표 참고) | 건강 정보를 다시 가리고 보호자에게 종료 전달 |

**취소:**

| 단계 | 취소하거나 끝내는 방법 |
|---|---|
| 질문 단계 | 음성 "괜찮아요" 또는 "괜찮아 취소해줘", 또는 조향·브레이크·방향지시등·기어·속도 변화. 아무것도 전송되지 않음 |
| 도움 요청 직후 | 음성 "괜찮아요" 또는 "괜찮아 취소해줘". 안전한 곳으로 가는 조작이 당연하므로 차량 조작으로는 취소되지 않음 |
| 응답 없음 확정 뒤 (보호자 연락, 기어 P, 잠금 해제 고지, 구조 단계) | **음성 "괜찮아 취소해줘"**("괜찮"과 "취소"가 함께 들릴 때), 또는 기어 P에서 화면 조작. "괜찮아요"만으로는 취소되지 않음. 구조자가 운전자에게 "괜찮아요?"라고 묻는 말일 수 있기 때문. **차량 조작으로도 취소되지 않음.** 동승자가 기어를 P로 넣으며 브레이크를 밟을 수 있기 때문 |
| 구조 단계 종료 | 화면의 종료 버튼 또는 음성 "종료". 음성 "괜찮아 취소해줘"는 취소로 끝냄 |

취소되면 "취소되었습니다"라고 말합니다. 이미 보낸 뒤 취소하면 보호자에게 취소 메시지가 가며, 누가 취소했는지는 알 수 없다고 적습니다. 응답 없음 확정 뒤에 조작이 있으면 취소 문구를 음성으로 알립니다.

**차가 다시 움직이면:** 응답 없음 확정 뒤 차가 3초 이상 계속 움직이면 그 정차에 대한 응답 없음은 유효하지 않다고 보고 잠금 해제 흐름을 멈춥니다. 음성으로 알리고 보호자에게 "다시 움직임"을 전하며, 운전자가 응답한 것인지 알 수 없으므로 취소 메시지는 보내지 않습니다. 다시 멈추면 처음부터 묻습니다. 그 사이 기어 P로 세워도 문 잠금을 풀지 않습니다. 3초보다 짧은 구름은 무시합니다. 고지 중에 기어가 P에서 빠지면 잠금을 풀지 않고 앞 단계로 돌아갑니다.

## 실제 호출과 시뮬레이션

| 기능 | 사용 API | 구분 |
|---|---|---|
| 음성 안내 | TextToSpeech 3.3.1 ON_DEVICE (키 불필요) | 실제 호출 |
| 음성 인식 | SpeechToText 3.3.1 ON_DEVICE (키 불필요) | 인식 엔진은 실제 호출. **입력은 합성 음성 파일이고 실제 마이크는 시험하지 않음** |
| 쉼터 내비 | NaviHelper 3.0.5 `requestRoute` | 실제 호출 |
| 조작 판단 | Vehicle 2.3.2 조향·브레이크·방향지시등, AAOS `GEAR_SELECTION`·`PERF_VEHICLE_SPEED` | 호출은 실제, 값은 Virtual Console 시뮬레이션 |
| 창문, 문 잠금, 실내등, 미등, 글러브박스 | Vehicle 2.3.2 | 호출은 실제. 글러브박스는 SDK 응답으로만 확인 |
| 위치 | FusedLocation 1.1.3 | 호출은 실제, 값은 시뮬레이션 |
| 보호자 전송 | 로컬 서버(`guardian-mock`) | **가상 전송.** 실제 문자·알림 경로는 정하지 않았고 시험하지 않음. 응답 없음 메시지는 보호자에게 119 신고 판단을 요청하고, 가상 보호자 화면에 신고 때 알려 줄 정보를 정리해 보여 줌. 병력은 보내지 않고 의료기관으로 전송하지 않음 |
| 쉼터 좌표 | 전국졸음쉼터표준데이터(공공데이터포털, 한국도로공사 제공, 데이터 기준일 2026-02-25) | 실제 공공데이터 중 **경기도 45건만** 수록. 직선거리로 고르며 도로 진행 방향은 보지 않음 |

## 제한 사항

- **기어가 P가 아니면 앱이 할 수 없는 일:** 문 잠금 해제, 실내등, 미등은 플랫폼이 오류 50001(`ERROR_DRIVING_RESTRICTED`)로 거부합니다. 앱은 기어를 바꿀 수 없습니다. 기어 D로 멈춘 차에 혼자 있으면 보호자 연락, 창문, 음성까지만 가능합니다. 구조 화면도 플랫폼이 가립니다.
- **비상등을 켜지 못합니다.** SDK에 메서드가 없고 AAOS 경로는 권한이 없습니다. 후방 안개등과 에어백 신호는 이 에뮬레이터에서 지원되지 않아 쓰지 않습니다.
- **응답 확인의 성능을 측정하지 않았습니다.** 신호 대기와 응답할 수 없는 상태를 차량 값만으로 구분할 수 없어 음성으로 묻습니다. 시연으로 증명할 수 있는 것은 흐름뿐입니다.
- **음성 호출은 상시로 듣지 않습니다.** 마이크는 응답을 기다리는 구간에만 씁니다. 그래서 release 빌드의 평소 상태에서 음성 호출을 시작할 방법은 없고 화면의 "도움 요청" 버튼이 있습니다. 호출 방법은 아직 정하지 않았습니다.
- **응답 없음 확정 뒤에는 깨어난 운전자가 차를 조작해도 취소되지 않습니다.** 누가 조작했는지 앱이 구분하지 못합니다. 조작이 있으면 음성으로 취소 방법을 알리고, 말하거나 기어 P에서 화면으로 취소해야 합니다. 말을 하지 못하면 기어 P에서 문 잠금이 풀립니다.
- **말한 사람을 구분하지 못합니다.** 응답 없음 확정 뒤에는 "괜찮아 취소해줘"로만 취소되지만, 운전자가 아닌 사람이 이 말을 해도 취소됩니다. "괜찮"과 "취소"가 우연히 한 문장에 들어가도 취소로 봅니다. 앱의 안내 문구에도 이 말이 들어 있어, 실제 차량에서 스피커 소리가 마이크로 들어가면 취소될 수 있습니다(마이크는 안내가 끝난 뒤에만 엽니다). 실제 마이크로 시험하지 않았습니다.
- 동승자가 브레이크를 밟고 기어를 P로 넣는 순서는 Virtual Console로만 확인했습니다. 실제 차량의 조작 순서는 확인하지 못했습니다.
- 미확인: 실차 동작, 실제 마이크, 시동 시 자동 시작, App Market의 제어 권한·포그라운드 서비스·주행 중 음성 승인, 제조사 정차 기능이 기어를 P로 두는지.
- 창문 폭 상한(30%)은 임시값입니다. 사람이 드나들 수 없는 폭은 실제 차량에서 확인해야 합니다.
- 동승자 안내 문구는 전문가 검토 전 초안입니다.
- 의료기기 해당 여부는 판단을 받지 않았습니다. 앱은 연락과 정보 표시만 하며, 앱 밖으로 병력을 보내지 않고 의료기관으로 전송하지 않습니다.

## 저장소 구성

- `app/`: Pleos Connect 앱 (Kotlin, Compose). `core/`는 Android에 의존하지 않는 판단 로직입니다.
- `guardian-mock/`: 보호자 가상 서버 (Node.js)
- `scripts/`: Virtual Console 조작, 시연·시험 자동화, 비밀값 검사
- `docs/`: 확인 결과, 시연 시나리오, 보안 점검
- 앱 표시 이름은 `app/src/main/res/values/strings.xml`의 `app_name` 한 곳에 있습니다.
